# Changelog

## Unreleased

- Settings and the rest of the app, apart from the Library page, are easier to use and no longer overlap, clip or show alarming errors. The Settings tabs now all fit on a tablet (the current tab no longer scrolls the first ones out of sight; narrower windows scroll with a fade), the sidebar's Plex-safety note is a tooltip when the sidebar is collapsed, notification details are a real button, and every (i) help button has a 24 px target. The server list has one name everywhere, "Connections" (Settings, then Connections), instead of "Servers page" or "Media Servers"; "What's New" reads Reprise's own releases instead of the upstream project's.
- Review-only setups see no false alarms. With preview thumbnails off (and chapter thumbnails, Intro & Credits and loudness off) Reprise no longer requires or checks the Plex config folder (`plex_config_folder_needed`); a wrong or read-only folder shows a muted note instead of a red error; and the Connections card says "Previews off" instead of "Previews on". A server Reprise cannot reach now says why in plain words and what to check, with the technical message behind Details, on the card, in the edit dialog and in the add flow.
- First-run setup reads in plain words: server types say "Sign in with your Plex account", the library step says to pick at least one library (the old line said to tick none to monitor all while Next stayed disabled), the path step asks to check one real file before anything about Plex's own folder, the "Can't reach plex.tv?" line no longer breaks apart on a phone, and step 4 shows only the graphics card with worker groups and thumbnails folded under Advanced.
- Connections: the Edit dialog's path tables fit at tablet width, a server that cannot be reached shows "Can't reach it" instead of a false "Connected", Setup Health explains its wait, and keyboard focus returns to the button you came from. Jobs: the status tabs wrap instead of being cut off, Quick actions is simpler, the System card says in plain words whether each connection is connected, failed or stopped jobs say what happened and what to do (technical text under "Technical details"), and Start new job uses plain names. Automation starts with the Sonarr/Radarr address to paste (one tab strip instead of three navigation layers), Schedules is a list with a friendly empty state, and Logs are readable at phone width. Advanced settings is about 45 % shorter (expert groups fold under one-line summaries, the section picker works on tablets, the title no longer wraps, worker-group names are readable), Sharing's "Add an app" stays on one line and uses Reprise's own confirmations, Library health and Inspector fit tablet width and the Inspector's file title no longer squashes, and Nodes' Add node fits a phone.
- A Library row that is not current now says why instead of always saying "File changed", and Refresh clears the rows it should. Live, 34 of 4,258 rows read "File changed" (Andor S1E2 among them) although nobody changed a file: Sonarr had upgraded those episodes (old file deleted, new one imported) and Plex had dropped the old media, so the old row's file was simply gone. The rows now read File missing (renamed, replaced or removed), File changed (edited in place), File unavailable, Media folder unavailable (storage not mounted yet), Library settings changed, Plex changed, Analyze again (Reprise's comparison method was updated, which is what every profile revision does to analyzed episodes) or Comparison changed, each with a sentence and the button that helps (`stale` on each item and on the open episode: `code`, `label`, `message`, `next`, `action` "refresh" or "analyze"); the lookup answer for clients is unchanged. Nothing could clear those rows: a refresh that could not read even one file (the 6:22 PM one: "2 skipped") skipped the clean-up for the whole library, and a scan of one new file never cleaned up at all. A refresh now removes the entries Plex no longer lists and keeps only those of the episodes it could not read, and a scan of just the new file (a Sonarr or Radarr webhook) also drops that episode's old row.
- Library page layout and usability fixes found on a 1280×720 tablet. The episode list no longer collapses to a sliver (rows overlapping, the help text on top of the first row) when Activity, finished jobs or ticked rows share the pane: the list is a scroller with guaranteed room, Activity is capped and scrolls under its own head, the selection bar is one row, and nothing spills out of the pane. A long episode title is no longer squeezed by the status and Analyze button (they wrap below it). The review no longer keeps showing an episode the filters leave out: it closes and says so, or stays open under a notice when there are unsaved changes. Below 1100 px the list stacks above the review. New: Select all, a "Review next" shortcut, "Season N" filter labels, a status line that stays in view and can be dismissed, "Play this section" scrolls the player into view, a file the browser cannot play no longer leaves an empty grey player, and the changed-file chip, sentence and next step follow the service's `stale` reason. A running job's percent no longer repeats on every episode of a multi-episode job.
- Analysis is about 3.6 times faster with the same results (Community S03E02 against its 3 nearest episodes, 50 min to 14 min on the busy NAS, every stage's output identical): a frame pair that cannot match stops at the first limit it exceeds instead of computing all seven; the spatial-information check uses exact integer sums; the ffprobe audit of a window runs beside the decode instead of before it (a failed audit still fails the scan, at its end); up to 3 references are searched at once (`REPRISE_ANALYSIS_WORKERS`, 1 to 8; results are merged in reference order, so they do not depend on which finishes first); with an NVIDIA GPU the frame-pair limits are first checked on it (`media_preview_generator/reprise/cuda_kernels/`: our own kernels shipped as PTX and loaded through the driver's `libcuda`, no CUDA toolkit in the image; a plane is decided on the GPU only when the CPU's float arithmetic is certain to give the same verdict, anything inside the error band is redone on the CPU, and the kernels are self-tested against the CPU on first use; `REPRISE_CUDA_VERDICT=0` turns it off); and the frames of a window scanned for one episode are kept per file generation (`reprise-scan-cache.db` in the config folder, 256 MB at most, least recently used out first) so the episodes that compare with it do not decode them again (a season scans 2.4 times fewer seconds of video). The Intel iGPU is not used to spread references (`REPRISE_SPREAD_DECODERS=1` tries it): its decode itself costs almost no CPU, but copying 10-bit frames back from it costs about as much as decoding on the CPU, so it measured 10 to 30 % slower than all references on the P40.
- The progress bar of an analysis moves from the start: the target's scan and every reference's scan report as they go (it used to stay at 0 % until the first reference was finished, minutes on a busy host).
- Reprise now uses online intro and credits times (IntroDB, SkipDB, and TheIntroDB when it has a key; the sources already under Settings > Intro & Credits) in two ways. As hints, they say where to search in the other episodes of the season: a hint only adds places to look, and the strict sound and picture confirmation decides exactly as before, so with no online data a result and its speed are unchanged. As suggestions, a time that comparing episodes could not confirm is stored as a proposed skip with `origin: "online"`, `reason_code: "online_suggestion"` and the label "Suggested by IntroDB — not confirmed by Reprise." (several databases read "A and B"); it is never eligible to skip until the owner approves that exact range. When Plex and a database agree within 5 seconds at both ends it is one range with `origin: "plex"` and the label "Suggested by Plex and IntroDB — not confirmed by Reprise."; an online time that overlaps a Plex marker of the same kind without agreeing is never added. Every suggestion now carries `suggested_by` (for example `["Plex", "IntroDB"]`; empty on other ranges, and on a Plex suggestion saved before this change, which is Plex's). An approved online suggestion can be sent to Plex like any other approved range; a Plex suggestion still never is. Library rows count both kinds in `ranges.suggested`.
- Added a single owner switch for those lookups, "Look up intro times online (IntroDB, SkipDB)", on the Library page next to the GPU line, with one sentence saying what is sent (the show's id, season, episode and the file's length, nothing else). It is `online_lookups` in `GET` and `PATCH /api/reprise/settings`, and it is on unless explicitly turned off, so a live install gets it with no step.
- The key that approves a suggestion is now `acknowledge_suggestion` and covers Plex and online suggestions; the older `acknowledge_plex_suggestion` is still accepted. On the Library page a suggestion's badge names who made it ("Plex suggestion", "IntroDB suggestion", "Plex + IntroDB suggestion", "IntroDB + SkipDB suggestion"), the inline question and the outcome sentence use the same names ("IntroDB found this, Reprise could not confirm it. Approve it only if it is right."), and the list count reads "N Plex suggestions" when every open suggestion is Plex's alone and "N suggestions" otherwise.
- The verification profile is revised to `v7`, so every earlier result is stale and needs a new analysis.
- Online times never make an analysis fail: a hinted search is skipped once the stretch the databases expect is half confirmed, an online window the decoder cannot compare (found live on Community S03E02, whose SkipDB credits time runs to the end of the file where the audio track ends before the picture) stays a suggestion with a plain note, and a failing hinted search is noted and dropped. A Plex marker that cannot be compared still fails the comparison as before.
- Added a per-server "Write preview thumbnails" switch (`output.preview_thumbnails`, on unless set to `false`). With it off, preview jobs and webhooks skip that server with a plain note and the Plex health check shows a read-only config folder as correct ("read-only (review only)") instead of a critical "not writable" error; with it on, a read-only or missing folder is still critical. The check now probes `Media/localhost`, where the bundles land, when it exists, and Jellyfin's off-media config-folder check is skipped when the switch is off.
- With "Write preview thumbnails" off, Setup Health also stops recommending anything that only matters to Reprise's own thumbnails: for Plex, its scan preferences, held scheduled jobs, chapter thumbnails and the advice to stop Plex's own BIF generation (which would have left Plex with no thumbnails at all); for Jellyfin and Emby, library flags, the plugin for tiles, trickplay geometry, extraction and the scheduled-task rows. One "Not needed: preview thumbnails are off" row replaces them, the servers are no longer probed for them, and the server-card issue count ignores them. Intro & Credits keeps its own Jellyfin/Emby plugin requirement. Turning the switch back on restores every recommendation.
- Fixed populated-library timeouts by checking playback identity and freshness only for the requested page, after filtering and deduplication.
- Introduced Reprise's library-first workflow for indexing Plex libraries, reviewing evidence and editing, approving or locking keep and skip ranges. Keep ranges veto overlapping skips; eligible skips remain disjoint. Detection proposes decisions, not approvals, and uncertain or changed evidence requires review.
- Added queued CPU-supported analysis, comparison previews and library refresh, with pause, resume and cancellation. Refresh and saved-result lookups do not implicitly start analysis. Conservative audio and video verification requires no GPU or language model.
- Adopted review-first, codec-tolerant native signal matching with mandatory owner approval. Tiny visual edits and quiet or brief changes may be missed; the interface and playback API documentation explain this limit. Changing the verification profile invalidates old approvals while retaining owner keeps and locks.
- Switched new image builds to a native FFmpeg 8.1.2 and matching ffprobe on PATH, while keeping the separate patched loudness binary. GPU acceleration and Dolby Vision Profile 5 colour accuracy are not established for this build.
- Changed image delivery to build one cold candidate, check source and license artifacts, FFmpeg configuration and startup health, then publish its full source-commit tag. The candidate passed independent holdout; full CI remains a launch gate, and production requires the independently accepted immutable digest. The earlier `ac40` two-cold-build comparison does not establish that current rebuilds are identical.
- Added a playback API using exact media and selected-audio identity, named scoped client credentials and stored credential hashes. It returns eligible skips only for current, approved results. The API can support a future Marquee integration; no Marquee client or TV deployment is included.
- Added guarded Plex publication: writes default off, review is separate from prepare and apply, incompatible projections are refused, interrupted writes are reconciled rather than blindly repeated, and undo refuses conflicting external changes.
- Retained Media Preview Generator and Recurring Content Detector attribution and license notices. Two upstream detector fixture videos with unverified redistribution rights were filtered from the imported history.
- Restored the Unraid icon URL with a 512×512 PNG rendered from the existing Reprise artwork.
- Added editable optional NVIDIA variables to the Unraid template and documented Intel device/group mapping, container recovery and the distinction between GPU visibility and the current CPU-only analysis/FFmpeg paths. Corrected the deployment documentation to match the accepted image already pinned by the examples.
- Documented complete review-only Plex and arr connection setup, case-sensitive Plex folder configuration and read-only cache/media mappings; distinguished tested webhook connectivity from thumbnail automation and native Reprise analysis. Added the optional Plex folder environment field to the Unraid template and linked the tracked GPU/UI work.
- Moved configured processing scratch defaults to `/config/tmp` on the appdata volume, avoiding the small `/tmp` tmpfs and its failed minimum-free-space validation; documented the separate Python `TMPDIR` setting and startup-directory requirement.
- Fixed single-episode analysis doing nothing on real files. The native audio timeline check now accepts the one-millisecond container-timestamp wobble that every Community episode has (the decoder revision is bumped, so results from earlier builds are re-analyzed), and a file's change time is no longer part of its identity, so a permissions, hard-link or mover pass can no longer turn a whole library stale. A replaced or edited file (new size, modification time or inode) still does.
- Every analysis now stores why it proposed nothing in plain sentences (no other episodes to compare, siblings not ready, compared but no repeat, failed and why) and shows it in the result, in the Library list (`reasons`, `ranges`) and in the queue (`media_version_ids`, `message`, `outcome`). Analyzing a changed or unknown file answers 409 with a sentence instead of 400 "Invalid request or operation". Legacy Intro & Credits jobs for which no server has it turned on now end with an amber "Nothing was checked" warning instead of a green success.
- Analysis no longer fails on Blu-ray rips with PGS subtitles (16% of one live library). The native video and audio decoders now ignore FFmpeg's "could not find codec parameters" warning for a subtitle stream they never decode; every other warning or error still fails closed.
- Analysis now checks the picture only for offsets whose sound already matched, an exact shortcut (a proposal with no matching sound can never be supported). On a real episode compared with two others this took 12 minutes where the same run was still working after 45. A comparison with several siblings is still a long CPU job, so the queue now says which episode is being compared.
- Plex's own intro and credits markers are now offered as suggestions. When comparing episodes cannot confirm a Plex marker for the exact file (nothing to compare with, no repeat, longer than the 3 minutes Reprise can compare, or an episode that cannot be compared exactly, such as HDR or a hole in the sound's timeline, which used to fail the whole analysis), it is stored as a proposed skip with `origin: "plex"` and the label "Suggested by Plex — not confirmed by Reprise" instead of a protective keep, and the result says why nothing was confirmed. It is never eligible to skip until the owner approves that exact range with an explicit acknowledgment (`acknowledge_plex_suggestion`); keep vetoes, freshness and the publication switch are unchanged, and it is never written back to Plex. A Plex marker ending up to a second after its file is fitted to it, and one that does not fit is ignored with a note: both used to fail the whole analysis (213 of 4,239 indexed files had one). Library rows report `ranges.suggested` and finished jobs the outcome `suggested`. The verification profile is revised (`v4`), so earlier results are re-analyzed.
- Analysis now compares an episode with at most the three nearest episodes of its season (by episode number, the lower number first on a tie, one file per episode) instead of up to six, as chosen by the owner.
- Added GPU decoding of analysis video with CPU fallback, superseding the "GPU acceleration is not established" notes above. FFmpeg 8.1.2 is now built with NVDEC (CUDA, through the MIT nv-codec-headers) and VA-API hardware decoding, still GPL with no non-free parts and with the new sources and notices retained; the image's Intel VA-API stack now loads Intel's media driver (its libva was too old, so every VA-API start failed and fell back to i965). Analysis decodes H.264 and HEVC 4:2:0 on a GPU that matched the CPU frame for frame on packaged reference clips; other streams and any failed GPU decode run on the CPU, and frames already read are never repeated or changed. The Library page shows the active decoder and a switch (`GET /api/reprise/settings` → `acceleration`; `{"gpu_decode": false}` turns it off) and comparison previews use the GPU the same way. On a Tesla P40 and an Intel UHD Graphics 630, 11 real episodes decoded frame for frame identically on the CPU, NVDEC and VA-API: NVDEC cut the decoder's CPU time by 26% (46% at 4K) and VA-API did not beat the CPU, while the ffprobe audit still decodes on the CPU, so a whole analysis finished only about 4% sooner. GPU passthrough settings are documented in the README.
- Replaced the token sign-in with an owner account. The first visit shows a "Welcome to Reprise" page to choose a username and password (8+ characters; stored only as a salted scrypt hash in `auth.json`); once an account exists that page is closed for good and every page asks for the username and password (with "Keep me signed in on this device"). Settings > Advanced > Account changes the password and signs out other browsers; a forgotten password is recovered from the container console with `python3 -m media_preview_generator.web.account_cli reset-password` or `reset-account` (no email). The token screen, `WEB_AUTH_TOKEN` sign-in, the setup wizard's token step, the token display/regenerate/set endpoints and the Automation "Webhook Secret" field are gone. The old token is not lost: the first start after upgrading copies it unchanged (`WEB_AUTH_TOKEN` if it was set, otherwise the one in `auth.json`) into the webhook secret, shown masked with Show, Copy and Regenerate in Settings > Connections, so Sonarr, Radarr, Plex, Emby, Jellyfin and scripts keep working with no change. Added a short five-step tour (Library, Analyze, Review, sending to Plex is off) that opens once for a new account, stays closed once skipped or finished (remembered on the server, so in every browser), and reopens from Settings or the sidebar. The session cookie is now named `reprise_session`, so another Flask app on the same host can no longer sign Reprise out.
- A damaged or unreadable `auth.json` (for example after changing PUID or PGID) no longer reopens the welcome page, so nobody can make a new account in place of the existing one. The sign-in page says the file can't be read and points to the reset command.
- Rebuilt the web interface around one shared shell. Every page now uses the Reprise sidebar (Library and Settings), the Rosé Pine palette and Manrope; the inherited upstream top navbar, its Ko-fi and Star links and its "Media Preview Generator" page titles are gone (GitHub issue #2). Settings holds eight tabs (Connections, Sharing, Automation, Advanced, Jobs, Logs, Inspector, Library health), with Nodes under Advanced and Webhook activity under Automation. The sidebar always says whether Reprise can change Plex ("Review only" or "Plex publishing is on"). The Plex publication switch and API clients moved from the Library page to a new Sharing page. The Library page shows plain-language statuses ("2 to review", "Nothing found", "Analysis failed", "File changed"), hides Plex, media, part and audio identifiers behind a collapsed "File details", explains every analysis outcome with a next step, shows live analysis progress in an Activity block and on the open episode, and reports whether analysis decodes on the GPU or CPU. The Inspector no longer offers its older "Check intro & credits" job when no server has that detector switched on (it queued a job that checked nothing); it links to Analyze in Library instead.
- The Library page shows a section Plex suggested apart from what Reprise found: a "Plex suggestion" badge (kept after approval as "Plex suggestion · approved by you"), an unfilled timeline bar, and an "N Plex suggestions" count beside "N to review". Approving one first asks "Plex found this, Reprise could not confirm it" and then sends the per-range `acknowledge_plex_suggestion` the server requires; there is no approve-all.
- A reboot no longer turns the whole library "changed on disk". Unraid's user-share mount comes back from a reboot with a new device number (4,218 of 4,239 indexed files on one live library after one reboot), and its mover gives a file moved between cache and array a new inode, so neither is part of a file's identity any more: a version is current while its size and modification time are unchanged; a replaced or edited file still goes stale. The device and inode are still recorded, and whether a reference is a hard link of the episode itself is now checked live on disk. The first library refresh after this update re-mints version IDs once.
- The recurrence engine now confirms real intros. Four things stood between it and any real file: (1) the picture and the sound of two episodes had to share one offset, but files of the same show carry slightly different sound/picture sync (Community S03E02 against E03: the sound sits 161.6 ms after the picture's offset), so the sound is now searched within ±250 ms of the picture's offset (cross-correlation of up to 12 s of the first audio track in 1-s blocks, whole-sample lags) and checked with the unchanged strict identity at its own offset, the picture at its own, with both offsets in the evidence (`reference_offset_ms`, `sound_offset_ms`); (2) frames now pair within one container tick of the stream (Matroska: 1 ms) instead of a fixed half millisecond, because two 24000/1001 fps rips keep whole-millisecond timestamps that land 0 or 1 ms apart, alternating, which had made the picture identity reject every real Blu-ray pair even when every frame matched, and the support of a matched pair is now the target frame's span, so that rounding no longer splits a run into pieces too short to anchor; (3) the subwoofer (LFE) channel can no longer veto alone: two AC-3 encodes of one mix disagree in it (r swinging between −0.57 and +0.99 on the pair above) while every other channel agrees at r = 0.99, so every main channel must still match sample-exactly and the evidence lists the channels compared (`checked_channels`); (4) a Plex marker now stays a Plex suggestion unless at least half of it is confirmed, with smaller confirmed fragments dropped and noted, instead of a one-second confirmed fragment replacing the whole-marker suggestion with a one-second skip. The picture is decoded only where the sound already matched (exact, and minutes faster when the sound matches in part), and the picture comparison itself got about a third faster with the same results (one integral image per plane instead of three). The verification profile is now `native-signal-review-first-v5`, so earlier results are re-analyzed.
- Analysis no longer fails on rips whose encoder wrote a user-data SEI message into every frame (every Rick and Morty episode in one live library: a 4.7 KB x264 message per frame, 15 MB of hex over one 97-s comparison window). The native frame reader printed and counted that payload against its 16 MB diagnostics cap and gave up with "can't be compared exactly"; the payload lines it ignores anyway no longer count, while real diagnostics and the per-line bound still do.
- Inside a Plex marker, Reprise now fills short gaps between the pieces it confirmed. Two lossy encodes of one episode fail some frames' picture limits (about 2 % between Blu-ray rips, about 50 % between web downloads) and each failure vetoes 250 ms either side, so a real intro was confirmed in fragments (Community S03E02 against E03: 5 s of the 27-s Plex intro) and dropped as a suggestion below half. A hole of at most 3.0 s between two confirmed pieces is filled when it lies entirely inside the Plex marker for the exact file and none of your keep ranges overlaps it; filled time counts towards the half a marker needs. Gaps over 3 s, anything outside the marker and files without a Plex marker are unchanged, and the result is still a proposal you approve. Filled gaps are recorded in the evidence (`bridged`, `bridge_start_ms`, `bridge_end_ms`, `bridge_length_ms`) and listed in the reasons ("Filled 4 short gaps (longest 2.1 s) inside Plex's intro."). The verification profile is now `native-signal-review-first-v6` (`bridge` section), so stored v5 results are re-analyzed on their next run.

Generated-media checks do not establish representative real-library accuracy, narrative safety or production-write safety. Plex writes remain off by default. See the [README](README.md) and [playback API guide](docs/reprise-api.md) for current behavior and limitations.
