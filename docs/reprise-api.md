# Reprise playback integration

Create a named client in Reprise under **Settings → Sharing → Add an app**. Copy its key (the secret) once; only its hash is retained. Send it in `Authorization: Bearer <secret>`, never in a URL. The default scopes are `results:read` and `jobs:read`; `analysis:request` is optional. These credentials cannot review, configure, publish, or stream media. Replace (rotate) or revoke a lost secret from the same page. Responses are `Cache-Control: no-store`.
Rotation revokes the old client and returns a **new client ID** with the replacement secret. Use the returned ID for subsequent rotation or revocation; the old ID is not an alias for the replacement.

The machine-readable contract is [reprise-openapi.yaml](reprise-openapi.yaml). The generic probe `tools/reprise_probe.py` sends a single saved-result lookup, does not enqueue analysis and does not print credentials. Set `REPRISE_TOKEN` in the environment and pass the Reprise base URL and all eight playback identity fields (see `--help`). Only use a trusted HTTPS connection, or a trusted local network.

## Playback safety

Supply the exact Plex machine identifier, rating key, media ID, part ID, token-free part key, part size in bytes, original-file duration in milliseconds and selected audio stream ID. Missing or mismatched identity is unresolved; do not guess a version. Lookups use saved results only and do not decode or schedule work. Only act on `eligible_skip_ranges` when resolution is `resolved`, status is `complete`, and freshness is `current`. Other states, including unapproved analysis, have no eligible skips. Ranges are half-open `[start_ms, end_ms)` in original-file presentation milliseconds, not transcoded timestamps. The `terminal` boolean is explicit; `false` is the default. Never infer it from proximity to the end.

**Marquee handoff:** Marquee's existing final-marker heuristic treats a marker near `duration - 2000ms` as final. Do not apply that heuristic to Reprise ranges: a brief scene or gag may follow a skip. Respect each exact end and explicit `terminal` value. Integrating and deploying Marquee changes is a separate task; no Marquee code is changed here.

Owner routes under `/api/reprise` use the existing owner authentication and CSRF protection. Review only saves decisions; publication requires separate prepare and apply operations and is disabled by default. A publication undo can refuse if another writer changed the data. Errors never include secrets. Two owner-only answers name the owner's own container folders so a missing mount can be fixed: the refusal of `PATCH /api/reprise/settings` when `writes_enabled` cannot be turned on, and the setup guide below.

**Publication replaces only the approved kinds.** `POST /api/reprise/publications/prepare` replaces Plex's markers of each kind (`intro`, `credits`) that is approved, and leaves the other kind exactly as Plex has it: its `taggings` rows keep their id, times and data, and its `pv:intros`/`pv:credits` entry in the part's `extra_data` stays byte-identical (so approving only credits keeps Plex's intro, and the reverse). Every existing row is still checked first, and an unsupported encoding or version of either kind refuses the change. Marker `index` values follow the legacy writer (one contiguous run per item, ordered by type then start), so a kept row's `index` changes only when that run needs it. `before_markers` and `after_markers` carry `unchanged: true` on each marker the change leaves exactly as it was. Undo restores the exact rows from before.

Owner `POST /api/reprise/refresh` accepts `{"server_id":"…","library_id":"…"}` and returns HTTP 202 with a job ID and `operation: "refresh"`. Poll `GET /api/reprise/jobs/<id>`; use `POST /api/reprise/jobs/<id>/pause`, `/resume`, or `/cancel` to control it. Completion includes `refresh` counts for registered, skipped, and removed entries. A scan that is cancelled or stops on an error removes nothing. A refresh of a whole library that could not read some episodes still did its job: it finishes as `completed` with a plain `warning` sentence, and `refresh.skipped_items` names each one as `{episode, reason}` (for example `{"episode": "Atlanta S03E08 New Jazz", "reason": "Plex and FFprobe can't read its audio/video streams (the file may be damaged or incomplete)"}`; the first 50 are named and `refresh.skipped` is always the full count). It still removes the entries Plex no longer lists (a file a Sonarr or Radarr upgrade replaced) and keeps only those of the episodes it could not read. Only a real failure (Plex unreachable, an error) makes a refresh `failed`; a scan of specific files (a webhook, or the refresh an analysis waits on) that could not read what it was asked for still ends `failed`. A scan of specific files also removes that episode's entries for media Plex no longer lists. A refresh only indexes the library and does not run analysis.

Owner Library responses (the media list and one episode's result) add `stale` to a row whose `freshness` is `stale`: `{code, label, message, next, action}`, otherwise `null`. `code` is `file_missing` (renamed, replaced or removed, as an upgrade does), `file_changed`, `file_unavailable`, `library_unavailable`, `library_changed`, `plex_changed`, `needs_reanalysis` (Reprise's comparison method was updated) or `comparison_changed`; `action` is `refresh` (refresh the library; analysis is refused) or `analyze` (analyze again). The playback lookup answer above is unchanged.

`plex_changed` means the episode's own binding to Plex really changed after the result was made: its file or part, the folder or path mapping, its library, show, season or episode, or Plex stopped listing it. What Plex changes by itself does not set it: the intro and credits markers it holds (Reprise's own sending changes them), the titles it shows and the address it was read at. `comparison_changed` is not stored: it reads while an episode this one was compared with is gone or bound differently, and the row is current again if that episode is as it was.

All Reprise job responses identify `operation` as `analysis`, `preview`, or `refresh`. The boolean `pause_requested` reports the job pause request, not proof that running work has already stopped. Terminal states are `completed`, `failed`, and `cancelled`. Only owner credentials can request library refreshes.

A restart does not fail an analysis or a refresh. The job goes back to `pending` and its response carries `recovery`: `{"state": "waiting" | "resumed" | "paused", "reason"?: …, "message": …}`. `waiting` ("Restarted. Analysis resumes in a moment.", or a message saying it waits for the media folders or for Plex) lasts until the start-up delay (`reprise_resume_delay_seconds`, default 120) has passed and the media can be reached; waiting for unavailable media never counts as an attempt. `resumed` ("Resumed after a restart") stays on the job while it runs and after it finishes. `paused` comes with `pause_requested: true` and a `reason`: `kept_stopping` (three automatic resumes within 15 minutes finished no episode: "Analysis paused: it kept stopping. Resume when ready."), `media_unavailable` (the folders or Plex were still unreachable after 30 minutes), `switched_off` (`reprise_auto_resume` is `false`) or `resume_failed`; `POST /api/reprise/jobs/<id>/resume` carries it on. A resume skips every episode that already finished and redoes only the one that was being read. An episode cut off twice is set aside: its `outcome.per_media` state is `set_aside` and that message and its `analysis.skipped_items` reason read "Skipped after 2 interrupted attempts — analyze it again to retry"; the job finishes `completed` with a `warning`. An episode Reprise cannot read (file missing or changed, unsupported, refused) is recorded once in the same way and never retried by a resume, and it no longer fails the job: the job is `failed` only when no episode produced a result. A job the owner cancelled stays `cancelled`. An interrupted refresh runs once more by itself; an interrupted preview ends `failed` ("This preview was interrupted by a restart. Create the preview again.").

## Setup guide status

Owner `GET /api/reprise/setup-guide` returns the seven-step checklist the web app shows a new install. It reads saved settings, a few folder checks, one indexed count and in-memory state: it makes no Plex call, does not walk the catalogue and writes nothing. A probe that fails does not fail the request; that step comes back `todo` with a reason that says it could not be checked.

The body is `{state, auto_open, required_total, required_done, all_required_done, steps}`. `state` is the owner's choice, `pending`, `dismissed` or `completed`; an install from before the guide existed has none saved, so it counts as `completed` when a media server is connected and as `pending` otherwise. `auto_open` is true when `state` is `pending` and a required step is open, which is what the home page uses to decide whether to open the guide. `steps` always holds seven objects in this order: `connect_plex`, `libraries_and_folders` and `refresh_library` (required, steps 1 to 3), then `gpu`, `online_lookup`, `webhooks` and `send_to_plex` (optional, steps 4 to 7).

Each step has `id`, `number`, `title`, `required`, `state` (`done`, `todo`, `blocked` while an earlier required step is open, or `working` while a job runs), `done` (`state` is `done`), `reason` (one plain sentence), `details` (extra plain lines, such as one per missing folder), `values` (`{label, value}` items worth copying, such as the webhook addresses), `action` (`{label, href}` for the existing page that does the step, or `null`), `help` (`{label, href}` for an external guide, or `null`), `progress` (`{percent}` while `working`, otherwise `null`) and `data` (machine-readable facts for tools and tests). The webhook secret is never in the payload; step 6 says where it lives (Settings, then Connections).

Owner `POST /api/reprise/setup-guide` accepts `{"state":"dismissed"}` (stop opening the guide by itself) or `{"state":"completed"}`, saves it in the owner account file and returns `{"state":"<saved state>"}`. Any other body is `400`; if the config folder cannot be written the answer is `500` with a plain `error`. Both routes are owner only: a client key gets `403`.

## Plex report

Owner `GET /api/reprise/report?show=<title>&season=<n>&format=json|text` compares, for each episode of one show or season, the markers Plex has now with what Reprise found, so one read answers "where do Plex's skips differ from Reprise's?". `show` is required (an exact title in any case, else a title that exactly one show contains; several matches, an unknown show or a season with no episodes is `400` with a plain `error`). `season` is optional, `format` defaults to `json`, and each may be given once. A client key gets `403`. It is read only: it reads Plex's markers in batches of 40 (`/library/metadata/<keys>?includeMarkers=1`, markers of type intro and credits only), reads the saved results and the publication journal, decodes nothing and writes nothing. If Plex cannot be reached the report still answers, `plex.status` says `unavailable` (or `partly`) and no Plex flag is raised.

The JSON body is `{schema_version, show, season, generated_at, tolerance_ms, plex: {status, message}, summary, episodes}`. `summary` has `episodes`, `analyzed`, `counts` (episodes per flag), `phrases` (one plain phrase per flag that occurred), `headline` (for example "3 episodes where Plex skips into a scene Reprise protects; 1 episode where the analysis failed"), `differs` and `needs_attention`. Each episode is one row: `id` (the media version id), `label` (`S3E06`), `title`, `verdict` (`ok`, `differs`, `needs_attention` or `pending`), `summary` (one plain sentence), `flags`, `analysis` (`status`, `freshness`, `stale`, plain `reasons`), `plex` (`status`, `markers: [{kind, start_ms, end_ms}]`, `unknown_kinds`), `reprise` (`skips` Reprise confirmed, `suggestions` it could not confirm, `owner_spans` the exact skips you set (see [Setting a skip exactly](#setting-a-skip-exactly)), `keeps` it protects, `to_review`, `approved`, which counts your exact skips too), `published` and `published_revision`. A flag is `{code, severity, kind, seconds, text}`:

- `plex_cuts_into_keep`: Plex's skip overlaps a keep you made, locked or reviewed (`keeps[].protected` is true), a scene you protected, by `seconds`.
- `plex_covers_unconfirmed` (severity `info`): Plex's skip overlaps a keep the analysis made (reason code `native_signal_unknown`; `protected` false) by `seconds`. That keep only says comparing episodes could not confirm the stretch; the analysis never records that content differs, so nothing is claimed to be a unique scene.
- `one_of_a_kind` (severity `info`, token `UNIQUE`): the intro or credits was compared with at least 3 other episodes and none shares it (nothing of it matched, or at most 2 s and a tenth of the suggested range), and Reprise confirmed no skip of that kind. `text` says how many episodes and whether only its sound matched (its own version). It is not `unconfirmed` and does not need attention. The facts are kept in the evidence metrics as `comparison` (`episodes_searched`, `sound_matched`, `picture_matched`, `confirmed_ms`); an analysis from before them is read only from its note "no repeating intro or credits could be confirmed", otherwise it needs a new analysis. The same sentence is in the result's `reasons`.
- `owner_span` (severity `info`, token `SET_BY_YOU`): you set the exact skip for this intro or credits yourself; `text` says which and where, for example "Set by you: the intro skip (1:00 to 2:20)". Your skip replaces everything else Reprise found for that kind, so nothing of that kind is compared with Plex's marker: it earns no `one_of_a_kind`, `unconfirmed`, `plex_covers_unconfirmed`, `plex_starts_early`, `plex_ends_late` or `plex_missing` flag. `plex_cuts_into_keep` still applies, because a scene you protected stays protected from Plex's marker too. The span is in `reprise.owner_spans`, not in `reprise.skips`.
- `plex_starts_early` / `plex_ends_late`: Plex's skip starts, or ends, `seconds` outside Reprise's skip. Plex ending at the end of the file is clamped to the file's length, and a Reprise skip that runs to the end is never "late".
- `plex_missing`: Reprise found an intro or credits skip and Plex has none (not raised for a kind the library hides from Plex).
- `unconfirmed`: Reprise has only suggestions (Plex's or online), nothing it confirmed.
- `not_analyzed`, `failed`, `stale`: there is no usable result, so nothing is compared with Plex; `analysis.reasons` gives the failure in plain words.
- `published`: the latest applied change for this episode in the publication journal is still in force (`published_revision`).
- `published_auto` (text token `AUTO_SENT`, "sent to Plex automatically"): the same, and Reprise sent it by itself. An episode that carries it does not carry `published`; the row's `published` boolean is still true.

Differences of 1 second or less are not flagged. Plex flags are only raised for a complete, current analysis. `format=text` returns `text/plain`, under 4 KB however big the season: a season is one line per episode (`S3E02 P i1:40-2:10 c20:00-21:40 | R i1:40-2:10 c20:00-21:20 | K 20:36-20:50 | CUTS_KEEP(c 14s) LATE(c 20s)`, with `P` Plex, `R` Reprise, `O` a skip you set yourself (only on an episode that has one, and the legend then ends ", O skip you set"), `K` scenes you protected, `U` ranges Reprise could not confirm), cut with a note if it would not fit; a whole show is one line per season. The Library's **Plex report** button opens the same report as a page (`/reprise/report`), which names a skip you set in the Reprise line ("set by you") and filters by it.

Each row also has `published_automatically`: true when `published` is true and the latest applied change was made by Reprise's own automatic sending (see [Automatic mode](#automatic-mode)), otherwise false.

## Setting a skip exactly

The owner can set the exact intro or credits skip for one episode, where Reprise found nothing, found it somewhere else or could not confirm it. It is one review edit, saved like any other (`PATCH /api/reprise/media/<media_id>/review` with the result's `expected_revision`), that names no existing range:

```json
{"expected_revision": 4, "edits": [{"range_id": null, "kind": "intro", "start_ms": 5000, "end_ms": 40000, "review_status": "approved", "acknowledge_owner_span": true}]}
```

`kind` is `intro` or `credits`; the times are whole milliseconds with `0 <= start_ms < end_ms <=` the file's length. The edit may also say `"action": "skip"` and `"locked": true`, and `review_status`, if given, must be `approved`; no other key is accepted ("A skip you set is always approved and locked. Give only its type (intro or credits) and its start and end times."). It must carry `"acknowledge_owner_span": true`, the owner's deliberate yes to this exact skip, as `acknowledge_suggestion` is for a suggestion. Without it, or with any other value, the whole review is refused with `400` ("An exact skip needs a deliberate yes: send acknowledge_owner_span: true with it.") and nothing is saved. One review sets at most one exact skip per kind ("Set one exact skip for the intro and one for the credits, not two of the same."); a new one for a kind replaces the owner's earlier one of that kind.

The saved range has `origin: "owner"` (`detector` is what the analysis found, `manual` a scene the owner protects, `plex` and `online` suggestions), `reason_code: "owner_span"` and the reason "Set by you": a skip, approved and locked, for every audio track the file can be played with. Nothing has to confirm it, so it has no evidence. **It replaces every other skip of its kind.** While it is approved, `eligible_skip_ranges` lists it instead of Reprise's own skips and suggestions of that kind; the Library no longer counts those as waiting for review; the Plex report compares nothing of that kind with Plex's marker; and sending to Plex writes it in place of every other skip of that kind, Plex's own marker included. It may start before, end after or bridge what the analysis could not confirm, and it may cover the analysis's own keeps (the ones that only say comparing episodes could not confirm a stretch). Only what the owner made stops it: a scene the owner protected, a keep they locked or approved, or a skip they set or locked for the other kind. If it would cover one, whichever edit made them clash, the review is refused with `400` and a plain sentence ("The intro skip you set would cover a scene you protected (from 1:00 to 1:10). Change the skip, or remove that first.") and nothing is saved.

The hard checks are the same as for any skip. The result must be complete and current (otherwise `409`, as for any review); both times must be inside the file; and because Plex cannot hold them, a skip that reaches into the last two seconds of the file, or a credits skip that starts in the first two, is refused with `400` ("The final two seconds cannot be projected safely to Plex" or "Plex cannot represent this credits start exactly"). The one exception is a credits skip that ends exactly at the file's end (`end_ms` equal to its length): Plex holds that exactly as its final credits marker, so the skip runs to the end, the episode's preview included, and Up Next appears where it starts.

A saved span is changed like any range, by its `range_id`. `{"range_id": "<id>", "review_status": "rejected"}` takes it out of use (the kind goes back to what Reprise found; there is no delete), and approving it again or moving it (`start_ms`, `end_ms`, `kind`) needs `"acknowledge_owner_span": true` again; a rejection does not. Turning it into anything but a skip is refused ("A skip you set stays a skip: reject it, or set it again."). Saving other edits leaves an approved span approved, where other approved skips fall back to `proposed` as usual, and a new analysis keeps it, as it keeps every locked range.

Sending it is the ordinary publication: `POST /api/reprise/publications/prepare` projects the span as that kind's one marker and `undo` puts back what Plex had. When its times are exactly the marker Plex holds there is nothing to write, and `prepare` answers `409` with "Plex already has exactly the skip you set, so there is nothing to publish"; a span that has come to cover something the owner protected is refused with the same plain sentence as a review. [Automatic mode](#automatic-mode) never sends or replaces it: an episode with any skip the owner set, even a rejected one, is left to the owner, and its note says "You set a skip yourself, so sending it is up to you."

## Automatic mode

Reprise can read new files, work through the rest of the library and send sure matches to Plex without being asked; the "Autopilot: automatic intro and credits" section of `DESIGN.md` says how, and the "Automatic mode" section of the README says how to turn it on. These routes only show and switch it. Both are owner only: a client key gets `403` with `{"error": "Owner access required"}`.

`GET /api/reprise/settings` and `PATCH /api/reprise/settings` carry one more field, `autopilot`. It is `null` when automatic mode could not start (everything else still works), otherwise:

```json
{
  "auto_send": true,
  "backfill": true,
  "alerts": true,
  "auto_send_endings": false,
  "status": {
    "queue_length": 12,
    "last_reconcile": "2026-11-22T09:30:00Z",
    "last_alert": {"kind": "problem", "title": "Plex backup failed", "at": "2026-11-22T08:10:00Z"},
    "auto_send_blocked": "Sending to Plex is switched off, so nothing is sent."
  }
}
```

- `auto_send` (default `true`): send sure matches to Plex automatically. It does nothing unless **Allow sending to Plex** (`writes_enabled`) is also on.
- `auto_send_endings` (default `false`): when the local vision model is very sure where the end credits start (its confidence is High), send that skip to Plex by itself. It does nothing unless **Allow sending to Plex** (`writes_enabled`) is also on, and it is independent of `auto_send`. Episodes only, never films or specials; never over a skip the owner set, took back or turned down, or over a range the owner or the analysis keeps or locked; Medium and Low are never sent. Each one is made the owner's own exact skip (review actor `reprise-auto`) and published like any automatic change, so it appears in `GET /approvals/automatic` and can be undone. If anything goes wrong after the skip was made, it is taken away again, the episode is as it was, and a phone alert says so.
- `auto_send_intros` (default `false`): the same for intros. It is **offered only while Reprise considers the local model's intros safe to send** (a code switch, off today): until then the key is absent from `GET`, and sending it in a `PATCH` is `400` like any unknown key, and no intro is ever sent from the local model.
- `backfill` (default `true`): analyse the rest of the library gradually, in the background.
- `alerts` (default `true`): send phone alerts.
- `status.queue_length`: files waiting in the jobs Reprise queued by itself, counting files a job has not listed yet.
- `status.last_reconcile`: the last time Reprise looked at Plex's listing for new or changed files, ISO 8601 in UTC, or `null` if it has not yet.
- `status.last_alert`: the latest alert actually sent, `{kind, title, at}`, or `null`. `kind` is `problem`, `resolved` (the "fixed" follow-up) or `test`; `at` is ISO 8601 in UTC.
- `status.auto_send_blocked`: one plain sentence saying why nothing is being sent automatically right now (sending to Plex is off, an earlier write needs checking, Plex's database could not be backed up, or sending is paused after a refusal), or `null` while it can send. It is also `null` when `auto_send` is off.

`PATCH` accepts `{"auto_send": true | false}`, `{"auto_send_endings": …}`, `{"backfill": …}` and `{"alerts": …}` (and `auto_send_intros` while it is offered), alone or together with the other keys, and every value must be a boolean. Anything else, an unknown key or an empty body is `400` with `{"error": "Invalid request or operation"}`. Without automatic mode (`autopilot` is `null`) it is `400` with `{"error": "Automatic work is not available right now."}` and nothing in the same request is changed. The answer is the same body as `GET`, after the change.

Owner `POST /api/reprise/alerts/test` takes no body and sends one test message to the phone, whether or not `alerts` is on. It answers `200` with `{"sent": true, "message": "Test alert sent. Check your phone."}`, or `{"sent": false, "message": "<one plain sentence>"}` when it could not (no token file, the alert server refused it with a code, or it could not be reached). Without automatic mode it is `400` with the same error as above. The token is read from `ntfy-token` in the config folder at the moment of sending and is never returned or logged.

Every change Reprise sends by itself is in the publication journal like any other and can be undone the same way; its change record has `actor: "reprise-auto"`.

## Phone alerts and their buttons

With automatic mode on, Reprise also messages the phone (ntfy topic `homelabber`, same token file as the problem alerts) in two cases: **suggestions are waiting** (one message per show and season, for example "Community S2: 3 sure ones, 2 to look at", with an **Approve & send 3** button when some are sure, and always an **Open** button for the To approve page), and **Reprise sent episodes to Plex by itself** (one batched message with **Undo** and **Open**). A season is told about again only when something new is waiting there (a new sure one, more sure ones or more to look at than last time). At most 3 messages go out in any rolling hour, none during quiet hours, and what is held back is sent later, never dropped. The public address in the buttons is `https://reprise.nateshome.net`; set the environment variable `REPRISE_PUBLIC_URL` to change it.

`GET /api/reprise/notifications` (owner only) answers `{"enabled": true, "quiet_from": "22:00", "quiet_until": "08:00", "last": {"title": "…", "at": "2026-11-22T09:30:00Z"} | null, "waiting": 0, "waiting_reason": null | "quiet_hours" | "limit"}`. The same object is `status.notifications` of `autopilot`. `quiet_from` and `quiet_until` are 24-hour `HH:MM` in the server's local time; the quiet period may cross midnight, and the same time twice means no quiet hours. `PATCH /api/reprise/notifications` takes `{"enabled": bool}`, `{"quiet_from": "HH:MM"}` and `{"quiet_until": "HH:MM"}`, alone or together; anything else is `400` with `{"error": "<plain sentence>"}` and nothing is saved. Without automatic mode both are `400`. The settings are stored as `reprise_notify`, `reprise_notify_quiet_from` and `reprise_notify_quiet_until`.

`POST /api/reprise/notify/act/<token>` is what the buttons call from the phone. It needs **no sign-in, no cookie and no CSRF token**: the address is the credential. The token is `v1.<payload>.<signature>`, signed with the webhook secret (HMAC-SHA256), bound to one action (`approve` or `undo`) and, for `approve`, to exactly the episodes listed in the message; it works **once** and expires after **6 hours**. Rotating the webhook secret ends every outstanding button. It answers `{"ok": bool, "message": "<one plain sentence>", …}`: `200` done, `409` nothing was done (for example nothing sure is left), `410` expired or already used, `403` signature not valid, `400` not a token, `429` too many requests, `503` automatic mode is not running. Approving never touches an episode that is not in the message, and one that has stopped being a sure match is skipped and counted. The token appears in the address, so access logs hold a spent single-use token but no secret.

## Approvals (the To approve page)

These owner-only routes back the **To approve** page (`/reprise/approve`). They carry out what the Library could already do, in one step per season. A client key gets `403`.

`GET /api/reprise/approvals` lists everything waiting for the owner from Reprise's own database and one batched read of what Plex serves now (a few calls, about a second for a few hundred episodes). What Plex already has is not work, so it is left out: a suggestion within a second of Plex's marker of that kind is not listed, and an approved skip that Plex serves exactly is not waiting to be sent, whoever put it there and whatever the result's revision. A Plex that cannot be read leaves everything listed, as it was. It answers `{"shows": [...], "totals": {"sure", "needs", "ready", "seasons"}, "sending": {"available", "enabled", "message"}}`. Each show has `sure`, `needs`, `ready` and `seasons`; each season has `show`, `season`, `label`, `episodes`, `sure`, `needs`, `ready` and `kinds` (`{"intro", "credits"}`, the split of `sure`). `sure` counts the High-confidence suggestions of the local vision check, exactly the ones `POST /api/reprise/approve-local-model` approves. `needs` counts the other suggestions that would change Plex. Both count skips. `ready` counts episodes whose approved skips Plex does not have yet. `sending` says whether Reprise can write to Plex and whether the owner turned sending on.

`GET /api/reprise/approvals/season?show=<title>&season=<n>` answers for one season, set against what Plex has now: `{"show", "season", "label", "sure": [...], "needs": [...], "ready": [...], "plex": {"status", "message"}, "changes": {"sure": {"lines", "counts"}, "ready": {"lines", "counts"}}, "sending"}`. Each `sure` or `needs` item has `media_version_id`, `how_sure` (`high`, `medium`, `low`, `confirmed` or null), `reason`, `revision` and `change` (`new`, `moved` or `unknown`, set against Plex's own marker; a suggestion Plex already has is not listed). `plex.status` says whether Plex could be read; a Plex that cannot be read is reported there, not as an error. `changes.*.lines` are plain sentences such as "Intro skip is added on 2 episodes where Plex has none."

`POST /api/reprise/approvals/send` takes `{"show", "season", "scope", "to_plex"}`. `scope` is `sure` (approve this season's sure ones as the owner's own exact skips, then send them) or `approved` (send what the owner approved earlier). `to_plex` defaults to `true`; with `false` it only approves. `scope: "approved"` with `to_plex: false`, or `to_plex: true` while sending is off, is `400` with a plain sentence. Plex is backed up before anything is written, each episode goes through the ordinary publication checks, and one episode that fails does not stop the others. It answers `{"show", "season", "scope", "approved", "sent", "failed", "already", "stopped", "backup", "message"}`: `approved` and `sent` list episodes with `media_version_id`, `label` and `span_ids` (`sent` also has `change_id`, the publication-journal record), `failed` gives a plain `reason` per episode, and `stopped` is one sentence when the run ended early. `already` lists the episodes where Plex holds exactly what was approved: nothing is written for them and it is not a failure. When that is all there was, `message` is "Plex already has these skips. Nothing to send." (otherwise null) and the season is no longer in the queue.

`POST /api/reprise/approvals/undo` takes `{"changes": [{"media_version_id", "change_id", "span_ids", "label"}]}` (1 to 500 entries, as `send` returned them; `change_id` is null for an approval that was never sent). It puts Plex back as it was for each `change_id`, through the publication journal's own undo, and takes back the approvals in `span_ids`. It answers `{"restored": [{"media_version_id", "label", "withdrawn"}], "failed": [...]}`.

`GET /api/reprise/approvals/automatic?days=<n>` lists what Reprise sent to Plex by itself and is still there, newest first (`days` is 1 to 30, default 30; anything else is `400`). Notices the owner cleared are left out, and so are ones marked read more than a week ago. It answers `{"sent": [{"change_id", "media_version_id", "show", "season", "episode", "label", "kinds", "sent_at", "span_ids", "origin", "read"}]}`. `read` is true once the owner marked it read. `kinds` is `["credits"]`, `["intro"]` or both; `sent_at` is seconds since 1970; `origin` is `local_model` (Reprise made the skip from the local model's High suggestion: `span_ids` are the skips an undo withdraws) or `sure` (the detector confirmed it: `span_ids` is empty). Send an entry's `media_version_id`, `change_id`, `span_ids` and `label` to `/approvals/undo` to put it back; an undone change leaves this list.

`POST /api/reprise/approvals/automatic/notices` marks those notices read or clears them (the To approve page's **Mark all as read** and **Clear all**, and the cross on a season's row). The body is `{"action": "read" | "dismiss", "change_ids": [<1 to 500 change ids from the list>]}` or `{"action": ..., "all": true}` for everything listed (exactly one of the two); anything else is `400`. It answers `{"marked": <how many>}`. Nothing in Plex or in the publication journal changes, a read mark never undoes a clear, and a clear is kept on the server, so it holds on every screen. A mark is forgotten after 30 days, with the change it belongs to. Owner only.

Example, clearing the whole list from a script: `curl -X POST -H "Authorization: Bearer $WEBHOOK_SECRET" -H 'Content-Type: application/json' -d '{"action":"dismiss","all":true}' https://<host>/api/reprise/approvals/automatic/notices`.

`POST /api/reprise/approvals/decide` takes `{"media_version_id", "expected_revision", "kind", "decision"}` and, optionally, `start_ms` and `end_ms` (a moved time), `span_id` and `range_ids`. `decision` is `skip`, `keep` or `restore`. `expected_revision` is the revision the page last read: a stale one is `409` (`{"error": "Conflict; refresh and try again"}`) and nothing is written. Every answer carries `revision` and an `undo` body that, sent back with `decision: "restore"`, takes the answer back.

The pictures the page shows are made by FFmpeg from the file itself, so they work for a format the browser cannot play. They are made a couple at a time, cached, and sent with `Cache-Control: private, max-age=300`. A file FFmpeg cannot read is `502` with a plain `error`.

- `GET /api/reprise/media/<id>/frame?t_ms=<ms>&w=<px>` is one JPEG still. `w` is one of 120, 160, 240, 320, 480, 640 or 960 (default 480).
- `GET /api/reprise/media/<id>/strip?start_ms=<ms>&step_ms=<ms>&count=<n>&w=<px>` is `count` stills `step_ms` apart as one JPEG row (default width 160).
- `GET /api/reprise/media/<id>/cuts?start_ms=<ms>&end_ms=<ms>` answers `{"cuts": [<ms>, ...]}`, the times in that stretch where the picture jumps to a different shot, ascending. The page uses it to snap a moved edge to the nearest cut.

## Reanalysis and job controls

Recurrence references must be actively registered in the Reprise store and belong to a different, numbered Plex episode on the same Plex machine, in the same known show and season. Alternate files or audio bindings of the same episode do not count, even if they have a different rating key. Missing, ambiguous, conflicting or changed binding metadata cannot establish an independent reference and is rejected rather than guessed. Without an admissible reference, recurrence cannot support a skip proposal; review and publication remain separate steps.

At most three such episodes are compared, the nearest ones that can be compared exactly with the target: by episode number, the lower number first on a tie, one file per episode, so the same library always gives the same references in the same order. An episode in another picture or audio format, or one that cannot be read, is passed over for the next nearest, and the result says how many were left out.

When evidence changes, reanalysis replaces untouched detector proposals, including provisional keeps. Manual ranges, review overrides and locks survive on the same media generation; retained skip overrides lose approval until reviewed again. A locked skip wins over the new run: the new run's skip, keep and suggestion pieces of the same kind are cut back to what lies outside the lock (a piece wholly inside it is dropped), so a lock is never shown twice with slightly different bounds. Results an earlier version stored with that overlap are repaired once at start-up (recorded in `reprise_repairs`); only ranges nobody decided are cut, and a cut approval falls back to proposed. An unchanged rescan retains its revision and approvals. This lets a newly available reference produce reviewable skips without obsolete detector keeps blocking them.

When an episode's binding really changes, the approvals of what the analysis found go back to `proposed` and the reviews that rested on them are set aside until the episode is analyzed again, but the exact skip you set keeps its approval, and it and every locked range keep their overrides: the file is the same file. An episode that was compared with the changed one is only marked `comparison_changed`; nothing of its own is set back. Start-up runs two one-time repairs, each recorded in `reprise_repairs` and neither writing to Plex: `owner-span-approval-1` approves again an exact skip that a refresh had set back to `proposed` (and restores its override), and `stable-provenance-1` stamps the comparisons made earlier with the provenance that ignores what Plex changes by itself, so a result that was current stays current.

**Suggestions.** The Plex intro and credits markers read for the exact file are the windows Reprise compares. A marker that recurrence confirms is an ordinary proposal. A marker that no comparison confirmed (there was nothing to compare with, it did not repeat, it is longer than the three minutes Reprise can compare, or the episode cannot be compared exactly, for example HDR or a hole in the sound's timeline) is stored as a proposed skip with `origin: "plex"`, `reason_code: "plex_suggestion"` and the reason "Suggested by Plex — not confirmed by Reprise."; `reasons` then says why nothing was confirmed. Times from the online databases (IntroDB, SkipDB and, with its key, TheIntroDB, as switched on under Settings → Intro & Credits) are offered the same way: one that comparing episodes could not confirm is stored with `origin: "online"`, `reason_code: "online_suggestion"` and the reason "Suggested by IntroDB — not confirmed by Reprise." (several names read "A and B" or "A, B and C"). Every suggestion names who made it in `suggested_by`, for example `["Plex"]`, `["IntroDB"]` or `["IntroDB", "SkipDB"]`; it is empty on every other range, and a Plex suggestion saved before online suggestions existed has it empty and is Plex's. When Plex and a database agree, within 5 seconds at both ends, it is one range with `origin: "plex"` and `suggested_by: ["Plex", "IntroDB"]` (reason "Suggested by Plex and IntroDB — not confirmed by Reprise."). An online time that overlaps a Plex marker of the same kind without agreeing with it is never added, and `reasons` says so. The evidence for a suggestion has verdict `unknown`, `reason_code` `plex_marker_unconfirmed` or `online_times_unconfirmed`, and the metrics `candidate_source` (`plex` or `online`) and `suggested_by`. Content that nothing confirmed and nobody suggested stays a protective keep, and a marker confirmed in part keeps the ordinary protection for the rest. A suggestion is never in `eligible_skip_ranges` until the owner approves that exact range, and a review edit that approves it, or changes one already approved, must carry `"acknowledge_suggestion": true`; otherwise the whole review is refused with `400` ("A suggested range needs a deliberate approval: send acknowledge_suggestion: true with that range.") and nothing is saved. The older key `acknowledge_plex_suggestion` is still accepted for any suggestion. Once approved it applies to every audio track of the file, under the same keep vetoes and freshness rules as any other range. An approved online suggestion can be sent to Plex like any other approved range (when the owner has turned sending on), because Plex does not have it; a Plex suggestion is never published back to Plex, which already has it. A Plex marker that ends more than a second after the file does not fit it and is ignored, with a note in `reasons`.

**Online lookups.** `GET /api/reprise/settings` returns `online_lookups` (a boolean) and `PATCH /api/reprise/settings` accepts `{"online_lookups": true}` or `false`, alone or together with `writes_enabled`, `gpu_decode` and `gpu_vram_cap_mb`; every value must be a boolean (`gpu_vram_cap_mb`, below, is the one exception), anything else is `400`. It is the owner's single switch for asking the public databases where an episode's intro and credits are. It is on unless explicitly turned off, so an existing install has it with no step. A lookup sends the show's id, season, episode and the file's length, nothing else, and uses the IntroDB, SkipDB and TheIntroDB switches and key already under Settings → Intro & Credits. The times are used two ways: as hints, to say where to search in the other episodes (a hint only adds places to look; the strict sound and picture confirmation decides exactly as before), and as the suggestions above. With the switch off, or when no database knows the episode, analysis gives the same result at the same speed as before.

**GPU memory limit.** `GET /api/reprise/settings` also returns `gpu_vram_cap_mb` (default 2048) and, under `acceleration`, a `compare` object that says whether the NVIDIA GPU comparison is available and running (`enabled`, `running`, `vram_cap_mb`, `budget_mb`, `pairs`, `cpu_rechecks`, `cpu_fallbacks`, `problem`). `PATCH` takes `{"gpu_vram_cap_mb": 4096}`, a whole number of megabytes from 256 to 16384; anything else (a boolean, `null`, text, a fraction, a number outside the range) is `400`. It is the most video memory the comparison may hold at once. The comparison also never uses more than the card's free memory less 1 GiB, gives everything back when the analysis ends, and measures fewer pairs at a time or falls back to the CPU when memory runs short; the saved results are the same either way.

A media generation is the file's path, size, modification time, duration and stream layout. The change time (ctime), device number and inode are recorded but ignored, so permission, hard-link or mover passes and a reboot of the Unraid user-share mount (which gives every file a new device number) do not make results stale; replacing or editing the file does. Analyzing a file that changed since the last refresh, or is no longer in the library, answers `409` with a plain sentence in `error`; every analysis stores its reason for proposing nothing as plain sentences in `reasons`.

Results from an older verification profile become stale immediately, even if previously approved; lookups return no eligible skips and do not start analysis. Review and publication refuse stale results. Reanalyze and review skips again after a profile change. Manual keeps and locks are retained; matching approvals survive only when the active profile and evidence are unchanged. The profile is now `native-signal-review-first-v9` (it compares files in one common form whatever their codec, bit depth, resolution or sound layout, looks a second either side of the picture's offset for where the sound lines up, and goes on to further episodes for a suggested window the nearest leave less than half confirmed), so every result saved before it is stale and needs a new analysis.

Eligibility means current matching evidence plus explicit owner approval, not proof that a scene is safe to skip. Signal matching tolerates normal encoding differences: tiny visual edits and quiet or brief changes may be missed. Review the original media before approval. Playback clients must use only `eligible_skip_ranges`, retain protected gaps, and never treat proposed ranges or ranking scores as automatic approval.

Matching evidence carries two offsets into the reference episode in its `metrics`: `reference_offset_ms` for the picture (it also places `reference_start_ms` and `reference_end_ms`) and `sound_offset_ms` for the sound, which may differ by up to 1000 ms (measured on one season's Blu-ray rips: up to about 400 ms) because two files of one show rarely share exact sound/picture sync; each also has an exact rational (`*_rational_ms`). `reference_speed` (exact: `reference_speed_rational`) is how fast the reference runs against this file: 1, or the ratio of the two frame rates for a sped-up copy (24/25 for a 25 fps copy of 24 fps footage); reference time is the speed times this file's time plus the offset. `sound_levels` gives, per audio track, the factor that brings the reference's sound to this file's level. `checked_channels` lists, per audio track, the channels that go into the one mono signal the sound comparison uses: every channel except a subwoofer (LFE) channel, which is left out.

For a suggestion (Plex's or an online database's) the owner's acknowledged approval of that exact range stands in for matching evidence. A Plex marker is a suggestion whenever comparing episodes confirmed less than half of it (confirmed time plus the filled gaps below); a smaller confirmed fragment inside it is not proposed on its own and `reasons` says how much was confirmed.

**Filled gaps.** Inside one Plex marker for the exact file, a hole of at most 3 seconds between two neighbouring pieces Reprise confirmed (sound and picture) is filled when it lies entirely inside the marker and none of the owner's keep ranges overlaps it. Each filled hole is its own `match` evidence window with `reason_code: "native_signal_bridged"` and metrics `bridged: true`, `bridge_start_ms`, `bridge_end_ms` and `bridge_length_ms` (every other evidence window carries `bridged: false` and null bridge fields); it names the reference of the piece before it in `reference_version_id`, has `reference_start_ms` and `reference_end_ms` null and null picture and sound offsets, because nothing was compared across the hole. Its skip range is an ordinary `detector` proposal (`reason_code: "native_signal_bridged"`) and needs the owner's approval like any other. `reasons` lists the fills in plain words, for example "Filled 4 short gaps (longest 2.1 s) inside Plex's intro." Holes longer than 3 seconds, holes reaching outside the marker, and files without a Plex marker are never filled and stay protective keeps. The verification profile is `native-signal-review-first-v9` with a `bridge` section (`max_gap_ms: 3000`, `suggested_window: true`); results made under v8 or earlier are stale.

Cancellation and result finalization share one job-state decision. If cancellation wins, the active analysis becomes cancelled and its old skip approvals are cleared. If the last result commits first, the job completes before a late cancel can change its state. Resume starts work only when an existing pause is successfully removed; completed, failed and cancelled jobs remain terminal. To run them again, explicitly request a new analysis.
