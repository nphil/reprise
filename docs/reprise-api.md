# Reprise playback integration

Create a named client in Reprise under **Settings → Sharing → Add an app**. Copy its key (the secret) once; only its hash is retained. Send it in `Authorization: Bearer <secret>`, never in a URL. The default scopes are `results:read` and `jobs:read`; `analysis:request` is optional. These credentials cannot review, configure, publish, or stream media. Replace (rotate) or revoke a lost secret from the same page. Responses are `Cache-Control: no-store`.
Rotation revokes the old client and returns a **new client ID** with the replacement secret. Use the returned ID for subsequent rotation or revocation; the old ID is not an alias for the replacement.

The machine-readable contract is [reprise-openapi.yaml](reprise-openapi.yaml). The generic probe `tools/reprise_probe.py` sends a single saved-result lookup, does not enqueue analysis and does not print credentials. Set `REPRISE_TOKEN` in the environment and pass the Reprise base URL and all eight playback identity fields (see `--help`). Only use a trusted HTTPS connection, or a trusted local network.

## Playback safety

Supply the exact Plex machine identifier, rating key, media ID, part ID, token-free part key, part size in bytes, original-file duration in milliseconds and selected audio stream ID. Missing or mismatched identity is unresolved; do not guess a version. Lookups use saved results only and do not decode or schedule work. Only act on `eligible_skip_ranges` when resolution is `resolved`, status is `complete`, and freshness is `current`. Other states, including unapproved analysis, have no eligible skips. Ranges are half-open `[start_ms, end_ms)` in original-file presentation milliseconds, not transcoded timestamps. The `terminal` boolean is explicit; `false` is the default. Never infer it from proximity to the end.

**Marquee handoff:** Marquee's existing final-marker heuristic treats a marker near `duration - 2000ms` as final. Do not apply that heuristic to Reprise ranges: a brief scene or gag may follow a skip. Respect each exact end and explicit `terminal` value. Integrating and deploying Marquee changes is a separate task; no Marquee code is changed here.

Owner routes under `/api/reprise` use the existing owner authentication and CSRF protection. Review only saves decisions; publication requires separate prepare and apply operations and is disabled by default. A publication undo can refuse if another writer changed the data. Errors do not include private paths or secrets.

Owner `POST /api/reprise/refresh` accepts `{"server_id":"…","library_id":"…"}` and returns HTTP 202 with a job ID and `operation: "refresh"`. Poll `GET /api/reprise/jobs/<id>`; use `POST /api/reprise/jobs/<id>/pause`, `/resume`, or `/cancel` to control it. Completion includes `refresh` counts for registered, skipped, and removed entries. A cancelled, failed, or incomplete scan never removes entries it did not see; skipped files make the refresh incomplete. A refresh only indexes the library and does not run analysis.

All Reprise job responses identify `operation` as `analysis`, `preview`, or `refresh`. The boolean `pause_requested` reports the job pause request, not proof that running work has already stopped. Terminal states are `completed`, `failed`, and `cancelled`. Only owner credentials can request library refreshes.

## Reanalysis and job controls

Recurrence references must be actively registered in the Reprise store and belong to a different, numbered Plex episode on the same Plex machine, in the same known show and season. Alternate files or audio bindings of the same episode do not count, even if they have a different rating key. Missing, ambiguous, conflicting or changed binding metadata cannot establish an independent reference and is rejected rather than guessed. Without an admissible reference, recurrence cannot support a skip proposal; review and publication remain separate steps.

At most the three nearest such episodes are compared: by episode number, the lower number first on a tie, one file per episode, so the same library always gives the same references in the same order.

When evidence changes, reanalysis replaces untouched detector proposals, including provisional keeps. Manual ranges, review overrides and locks survive on the same media generation; retained skip overrides lose approval until reviewed again. An unchanged rescan retains its revision and approvals. This lets a newly available reference produce reviewable skips without obsolete detector keeps blocking them.

**Suggestions.** The Plex intro and credits markers read for the exact file are the windows Reprise compares. A marker that recurrence confirms is an ordinary proposal. A marker that no comparison confirmed (there was nothing to compare with, it did not repeat, it is longer than the three minutes Reprise can compare, or the episode cannot be compared exactly, for example HDR or a hole in the sound's timeline) is stored as a proposed skip with `origin: "plex"`, `reason_code: "plex_suggestion"` and the reason "Suggested by Plex — not confirmed by Reprise."; `reasons` then says why nothing was confirmed. Times from the online databases (IntroDB, SkipDB and, with its key, TheIntroDB, as switched on under Settings → Intro & Credits) are offered the same way: one that comparing episodes could not confirm is stored with `origin: "online"`, `reason_code: "online_suggestion"` and the reason "Suggested by IntroDB — not confirmed by Reprise." (several names read "A and B" or "A, B and C"). Every suggestion names who made it in `suggested_by`, for example `["Plex"]`, `["IntroDB"]` or `["IntroDB", "SkipDB"]`; it is empty on every other range, and a Plex suggestion saved before online suggestions existed has it empty and is Plex's. When Plex and a database agree, within 5 seconds at both ends, it is one range with `origin: "plex"` and `suggested_by: ["Plex", "IntroDB"]` (reason "Suggested by Plex and IntroDB — not confirmed by Reprise."). An online time that overlaps a Plex marker of the same kind without agreeing with it is never added, and `reasons` says so. The evidence for a suggestion has verdict `unknown`, `reason_code` `plex_marker_unconfirmed` or `online_times_unconfirmed`, and the metrics `candidate_source` (`plex` or `online`) and `suggested_by`. Content that nothing confirmed and nobody suggested stays a protective keep, and a marker confirmed in part keeps the ordinary protection for the rest. A suggestion is never in `eligible_skip_ranges` until the owner approves that exact range, and a review edit that approves it, or changes one already approved, must carry `"acknowledge_suggestion": true`; otherwise the whole review is refused with `400` ("A suggested range needs a deliberate approval: send acknowledge_suggestion: true with that range.") and nothing is saved. The older key `acknowledge_plex_suggestion` is still accepted for any suggestion. Once approved it applies to every audio track of the file, under the same keep vetoes and freshness rules as any other range. An approved online suggestion can be sent to Plex like any other approved range (when the owner has turned sending on), because Plex does not have it; a Plex suggestion is never published back to Plex, which already has it. A Plex marker that ends more than a second after the file does not fit it and is ignored, with a note in `reasons`.

**Online lookups.** `GET /api/reprise/settings` returns `online_lookups` (a boolean) and `PATCH /api/reprise/settings` accepts `{"online_lookups": true}` or `false`, alone or together with `writes_enabled` and `gpu_decode`; every value must be a boolean, anything else is `400`. It is the owner's single switch for asking the public databases where an episode's intro and credits are. It is on unless explicitly turned off, so an existing install has it with no step. A lookup sends the show's id, season, episode and the file's length, nothing else, and uses the IntroDB, SkipDB and TheIntroDB switches and key already under Settings → Intro & Credits. The times are used two ways: as hints, to say where to search in the other episodes (a hint only adds places to look; the strict sound and picture confirmation decides exactly as before), and as the suggestions above. With the switch off, or when no database knows the episode, analysis gives the same result at the same speed as before.

A media generation is the file's path, size, modification time, duration and stream layout. The change time (ctime), device number and inode are recorded but ignored, so permission, hard-link or mover passes and a reboot of the Unraid user-share mount (which gives every file a new device number) do not make results stale; replacing or editing the file does. Analyzing a file that changed since the last refresh, or is no longer in the library, answers `409` with a plain sentence in `error`; every analysis stores its reason for proposing nothing as plain sentences in `reasons`.

Results from an older verification profile become stale immediately, even if previously approved; lookups return no eligible skips and do not start analysis. Review and publication refuse stale results. Reanalyze and review skips again after a profile change. Manual keeps and locks are retained; matching approvals survive only when the active profile and evidence are unchanged. The profile is now `native-signal-review-first-v7` (it adds online times as hints and suggestions), so every result saved before it is stale and needs a new analysis.

Eligibility means current matching evidence plus explicit owner approval, not proof that a scene is safe to skip. Signal matching tolerates normal encoding differences: tiny visual edits and quiet or brief changes may be missed. Review the original media before approval. Playback clients must use only `eligible_skip_ranges`, retain protected gaps, and never treat proposed ranges or ranking scores as automatic approval.

Matching evidence carries two offsets into the reference episode in its `metrics`: `reference_offset_ms` for the picture (it also places `reference_start_ms` and `reference_end_ms`) and `sound_offset_ms` for the sound, which may differ by up to 250 ms because two files of one show rarely share exact sound/picture sync; each also has an exact rational (`*_rational_ms`). `checked_channels` lists, per audio track, the native channels the strict sound identity compared: every channel except a subwoofer (LFE) channel, which never vetoes on its own.

For a suggestion (Plex's or an online database's) the owner's acknowledged approval of that exact range stands in for matching evidence. A Plex marker is a suggestion whenever comparing episodes confirmed less than half of it (confirmed time plus the filled gaps below); a smaller confirmed fragment inside it is not proposed on its own and `reasons` says how much was confirmed.

**Filled gaps.** Inside one Plex marker for the exact file, a hole of at most 3 seconds between two neighbouring pieces Reprise confirmed (sound and picture) is filled when it lies entirely inside the marker and none of the owner's keep ranges overlaps it. Each filled hole is its own `match` evidence window with `reason_code: "native_signal_bridged"` and metrics `bridged: true`, `bridge_start_ms`, `bridge_end_ms` and `bridge_length_ms` (every other evidence window carries `bridged: false` and null bridge fields); it names the reference of the piece before it in `reference_version_id`, has `reference_start_ms` and `reference_end_ms` null and null picture and sound offsets, because nothing was compared across the hole. Its skip range is an ordinary `detector` proposal (`reason_code: "native_signal_bridged"`) and needs the owner's approval like any other. `reasons` lists the fills in plain words, for example "Filled 4 short gaps (longest 2.1 s) inside Plex's intro." Holes longer than 3 seconds, holes reaching outside the marker, and files without a Plex marker are never filled and stay protective keeps. The verification profile is `native-signal-review-first-v7` with a `bridge` section (`max_gap_ms: 3000`, `plex_marker: true`); results made under v6 or earlier are stale.

Cancellation and result finalization share one job-state decision. If cancellation wins, the active analysis becomes cancelled and its old skip approvals are cleared. If the last result commits first, the job completes before a late cancel can change its state. Resume starts work only when an existing pause is successfully removed; completed, failed and cancelled jobs remain terminal. To run them again, explicitly request a new analysis.
